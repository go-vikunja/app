### 1.1 Material and Cupertino are now separate packages, which affects every UI choice

- Flutter 3.47 published **`material_ui` 1.x and `cupertino_ui` 1.x** on pub.dev (publisher flutter.dev). Opt in with `dart fix --apply --code=migrate_design_widgets`. The in-SDK `package:flutter/material.dart` still exists in 3.47.5 ([V-sdk] `packages/flutter/lib/material.dart`). The official migration page says it is "scheduled for formal deprecation in an upcoming stable release" ([V-web] https://docs.flutter.dev/release/breaking-changes/material-ui-and-cupertino-ui.md). The 3.47 blog names the "Fall stable release in November" ([V-web]).
- **Types differ across the two libraries.** A `ColorScheme` from `material_ui` cannot be passed where a `flutter/material` `ColorScheme` is expected. `MaterialUiCompatibilityBridge` only bridges `Theme.of`/`MaterialLocalizations.of` lookups ([V-web] same page). In `material_ui` 1.6.0 the bridge is **already `@Deprecated`**: `flutter analyze` reports "MaterialUiCompatibilityBridge is a temporary migration utility…" ([V-build]).
- Packages that have already moved to `material_ui`: **go_router 18.0.0** ("Migrates to material_ui and cupertino_ui"), **cached_network_image 4.0.0**, **dynamic_color 2.0.0**, **flex_color_scheme 9.0.0**, **auto_route 11.2.0** ([V-pub] changelogs and dependency lists). `flutter_widget_from_html_core` 0.18.0-beta.1 depends on `material_ui ^1.2.0` ([V-pub]).
- I grepped the resolved sources for imports of `package:flutter/material.dart` or `cupertino.dart` versus `material_ui`/`cupertino_ui` ([V-build], script output in this session):
  - Already on `material_ui`: cached_network_image, dynamic_color, flex_color_scheme, go_router.
  - Still on the legacy library: flutter_quill (67 imports), kalender (16), flutter_markdown_plus (8), alchemist (10), and 1 or 2 imports each in flutter_riverpod, flutter_slidable, flutter_widget_from_html_core 0.17.4, webview_flutter, home_widget, patrol and flutter_web_auth_2.
  - Pure plugins with no UI: drift_flutter, workmanager, flutter_local_notifications, flutter_secure_storage, local_auth, native_dio_adapter.
- **gen-l10n still emits legacy delegates.** The 3.47.5 template imports `package:flutter_localizations/flutter_localizations.dart`, and the generated `localizationsDelegates` lists `GlobalMaterialLocalizations.delegate`, `GlobalCupertinoLocalizations.delegate` and `GlobalWidgetsLocalizations.delegate` from that legacy package ([V-sdk] `packages/flutter_tools/lib/src/localizations/gen_l10n_templates.dart:10,89-93`). With `material_ui`, compose the list yourself: `[AppLocalizations.delegate, ...mui.GlobalMaterialLocalizations.delegates]`, and import the legacy package with a prefix ([I]).

**Decision [I]:** start the app on `material_ui` ^1.6.0 and `cupertino_ui` ^1.1.2 from day one. It is a new codebase, so there is nothing to migrate, and the alternative is a forced migration within about a month. Keep the deprecated bridge in `MaterialApp.builder` only while legacy-importing dependencies remain, and prefer dependencies that do not expose Material types in their public API.

## 3. Detailed findings per area

### 3.1 State management and DI: Riverpod 3

- flutter_riverpod/riverpod/hooks_riverpod **3.4.3** (2026-09-03), riverpod_annotation **4.0.7**, riverpod_generator **4.0.9**, riverpod_lint **3.1.9**. All require Dart `^3.12.0`; riverpod_lint requires `>=3.13.0-0` [V-pub].
- Relevant 3.x features [V-pub, flutter_riverpod changelog]:
  - Automatic retry: the provider is flagged "loading" while retrying, and `AsyncValue.retrying` exists.
  - Mutations work without codegen and expose `MutationState.isPending/isSuccess`.
  - Providers pause when out of view via `TickerMode`; `Ref.isPaused` reports it (3.2.0).
  - `Ref.mounted` race fix (3.2.0).
  - `Ref.onManualInvalidation` (3.3.2).
  - Experimental offline persistence; `provider.future` skips persisted state by default.
  - Breaking: errors rethrown through `ref.watch` are wrapped in `ProviderException`.
  - `family.overrideWith` is deprecated in favour of `overrideWith2`, which becomes `overrideWith` in 4.0.0 (3.2.0).
- riverpod_generator 4.0.0: "Generated providers are no-longer constant" [V-pub].
- Why Riverpod [I]:
  1. Drift `watch()` streams map 1:1 to `StreamProvider`, which gives an offline-first UI with the DB as the single source of truth.
  2. The same repository graph can be built in headless isolates (workmanager callback, `onDidReceiveBackgroundNotificationResponse`, home_widget interactivity) with a plain `ProviderContainer()`, without a widget tree.
  3. One tool covers both DI and state.
- Bloc remains solid ([V-pub]: bloc 9.2.1 on 2026-05-12, flutter_bloc 9.1.1 on 2025-05-02, 160 points) but needs get_it/injectable for DI and has no headless-container story. signals 7.1.0 is niche (24k dl/30d).
- Riverpod 3 says a 4.0 may follow "relatively soon" (3.0.0-dev.12 notes) [V-pub]. The risk is moderate.

### 3.2 Local database: Drift on sqlite3 3.x build hooks

- drift **2.35.2** (2026-10-07), drift_dev **2.35.1**, drift_flutter **0.3.1**, sqlite3 **3.7.0** [V-pub].
- **sqlite3 3.0.0 switched to Dart build hooks**: "Use build hooks to load SQLite instead of DynamicLibrary… drop your dependencies on sqlite3_flutter_libs and sqlcipher_flutter_libs" [V-pub sqlite3 changelog]. `sqlite3_flutter_libs` is published as **0.6.0+eol** ("Deprecate this package") [V-pub]. drift 2.32.0 migrated to sqlite3 3.x [V-pub].
- Supply chain [V-src: pub cache `sqlite3-3.7.0/doc/hook.md`]:
  - By default the hook downloads prebuilt SQLite from immutable GitHub releases and verifies sha256 hashes shipped in the pub package.
  - Options under `hooks: user_defines: sqlite3:`:
    - `source: sqlite3 | sqlite3mc | sqlcipher | system | process | executable | source`
    - `url_pattern` for an artifact mirror
    - `path:` to a `sqlite3.c` to compile from source (needed for F-Droid policy [I])
  - Hook downloads respect `HTTPS_PROXY` (3.1.1).
  - Default compile options include FTS5, math functions, session and preupdate hooks.
- Encryption: `source: sqlite3mc` (SQLite3MultipleCiphers) or `sqlcipher` [V-src hook.md]. Recommendation [I]: **no DB encryption by default**. Rely on iOS Data Protection and Android file-based encryption, and keep secrets only in the Keychain/Keystore. An encrypted DB would need its key available to background isolates, which brings back the keychain-accessibility constraints of §3.7.
- **Cross-isolate access:** `driftDatabase(name:, native: DriftNativeOptions(shareAcrossIsolates: true, databasePath: …))` starts one DB server isolate found through `IsolateNameServer`. Every engine in the process (UI, workmanager, notification-action isolate, home_widget callback) shares it. You must `close()` explicitly to stop it [V-pub drift_flutter README]. `IsolateNameServer` is per process, so the iOS widget extension (a separate process) **cannot** use it [I].
- Measured: `libsqlite3.so` is 1.73 MB uncompressed (arm64) [V-build].
- Alternatives:
  - sqflite 2.4.4+1: still maintained and Flutter Favorite, but untyped and without reactive queries. It is pulled in transitively by flutter_cache_manager anyway [V-build].
  - ObjectBox 5.3.2 (6.0.0-preview.4 on 2026-10-06; objectbox_flutter_libs is CocoaPods-only) [V-pub].
  - Isar: `isar` 3.1.0+1 last released 2023-04-25 with SDK `<3.0.0`; the `isar/isar` repo was last pushed 2025-06-14. Community fork `isar_community` 3.3.2 (2026-03-23; repo isar-community/isar-community pushed 2026-09-08) [V-pub, GitHub API].
  - realm 20.2.0 (CocoaPods-only; MongoDB has deprecated Atlas Device SDKs [I]).
  - powersync 2.4.0 needs its own sync service, so it does not fit Vikunja.

### 3.3 Widget data path (decided here because it constrains the DB)

- Do **not** put the drift database in the iOS App Group container. iOS kills suspended processes that hold SQLite or file locks in shared containers (exception 0xdead10cc). GRDB's own guide calls sharing a DB "very difficult"; the advice is to keep SQLite out of the group container [V-web] https://mjtsai.com/blog/2025/05/15/sqlite-databases-in-app-group-containers-dont/ and https://developer.apple.com/forums/thread/655225.
- Instead, the app or background isolate writes **small precomputed JSON snapshots per widget configuration**:
  - `HomeWidget.saveWidgetData(key, json)` stores to `UserDefaults(suiteName: group)` on iOS and SharedPreferences on Android.
  - `HomeWidget.saveFile` writes larger payloads and stores the absolute path under the key.
  - Then call `HomeWidget.updateWidget(...)`.
  - [V-web] https://raw.githubusercontent.com/ABausG/home_widget/main/docs/usage/sync-data.mdx

### 3.4 HTTP client, TLS, self-signed certificates, proxies

- dio **5.11.1** (2026-09-04), native_dio_adapter **1.8.0** (2026-07-29; needs Flutter `>=3.35.6`, jni ^1.0.0), cronet_http **1.10.0** (2026-09-29), cupertino_http **3.1.0** (2026-09-03; **min iOS 15**) [V-pub].
- Why native stacks [V-pub READMEs]: system proxies and VPN, HTTP/3, the platform trust store, and cancellation.
  - native_dio_adapter supports request cancellation (1.5.1) and has an opt-in `createFallbackAdapter` for devices whose Cronet providers are disabled (1.7.0).
  - cronet_http 1.10.0 adds `useBuiltInDnsResolver: false` to work around `ERROR_HOSTNAME_NOT_RESOLVED` with QUIC "in background isolates" (dart-lang/http#1217).
- **dart:io does not honor user-installed CAs on Android**: dart-lang/sdk#50435 "HttpClient should honor user-installed certificates on Android" is open [V-web GitHub API]. Proxmox switched its Flutter app to cronet_http for this reason [V-web] https://lists.proxmox.com/pipermail/pve-devel/2025-September/074905.html.
- For self-hosters on Android: ship `res/xml/network_security_config.xml` with `<base-config><trust-anchors><certificates src="system"/><certificates src="user"/></trust-anchors></base-config>`. Apps targeting API 24+ do not trust user CAs without it [V-web Android docs, via search]. If plain-http LAN servers must be supported, also allow cleartext [I]. Cronet uses the platform verifier, so NSC applies [I, consistent with the Proxmox report].
- iOS: user-installed and trusted configuration profiles are honored by NSURLSession [I]. ATS blocks plain http unless `NSAllowsLocalNetworking`/exceptions are set [I].
- **Self-signed "trust this certificate" and mTLS [I]:** Cronet has no per-request override. For such servers, swap that server's dio instance to `IOHttpClientAdapter(createHttpClient: …, validateCertificate: (cert, host, port) => sha256(cert.der) == pinned)` [V-pub: dio 5.11.1 `lib/src/adapters/io_adapter.dart:36-37`]. Use a `SecurityContext` with a PKCS#12 client certificate for mTLS. This per-server adapter switch is the decisive reason for dio over `package:http`.
  - **Corrected in step 35b ([D65](../decisions.md#d65-connection-settings-per-server-address-in-the-apps-transport-a-certificate-pinned-in-the-tls-handshake-or-a-trusted-ca-certificate-a-client-certificate-access-headers-and-unencrypted-connections-only-with-consent-failing-closed)):** do not pin with `validateCertificate`. In dio 5.11.1 it runs after the request was sent and the response headers arrived, and only for a chain the `SecurityContext` already accepted, so a self-signed server fails before it is asked and an impostor would get the token first. The app pins in the TLS handshake instead (`SecurityContext(withTrustedRoots: false)` and a `badCertificateCallback` that compares the leaf's SHA-256), and one adapter in the base `Dio`s sends only the servers that need it through `dart:io`, rather than swapping a server's `Dio`.
- **Build blocker, verified:** with Flutter 3.47.5 / AGP 9.1.0 the first `flutter build apk --debug` **failed** in `processDebugMainManifest` with "Namespace 'org.chromium.net' is used in multiple modules… cronet-api:141.7340.3, cronet-shared:141.7340.3" [V-build `scratchpad/build_apk.log`].
  - This is the open issue https://github.com/dart-lang/http/issues/1932 (upstream https://issues.chromium.org/issues/406926302).
  - Workaround verified: add **`android.uniquePackageNames=false`** to `android/gradle.properties`; the build then succeeds [V-build `build_apk2.log`].
- Size [V-build, arm64 release split APK of the full smoke app]:
  - **24.0 MB** with Play-Services Cronet.
  - **30.5 MB** with `--dart-define=cronetHttpNoPlay=true`; embedded `libcronet.143.0.7445.0.so` is 6.5 MB.
  - For F-Droid/no-GMS builds use embedded Cronet, or `NativeAdapter(createFallbackAdapter: (_, __) => IOHttpClientAdapter())` [V-pub README]. Note that the IO fallback loses user-CA support.
- Retry/backoff: write a small dio interceptor [I]. dio_smart_retry 7.0.1 was last released 2024-10-22 [V-pub].
- Vikunja-specific: rate limiting and `Retry-After` exist (frontend refresh handles a `rate-limited` failure kind with `retryAt` from `Retry-After`) [V-src `.agents/docs/api.md` "Frontend clients"].

### 3.5 JSON models, codegen and the OpenAPI question

- freezed **4.0.2** (2026-09-18; requires Dart `>=3.13.0`, analyzer 14) [V-pub]:
  - Supports Dart 3.13 **primary constructors**.
  - Breaking: "No-longer support final keyword inside constructor parameter… Dart 3.13 no-longer allowing this syntax".
  - Still uses freezed_annotation **3.1.0**.
- json_serializable **6.14.1**, json_annotation **4.12.0**, build_runner **2.16.2** (2026-10-07) [V-pub].
- Verified codegen chain [V-build `scratchpad/gentest`]:
  - One `dart run build_runner build` ran riverpod_generator, retrofit_generator, freezed, json_serializable, go_router_builder and drift_dev together and printed "Built with build_runner/aot in 20s; wrote 18 outputs".
  - `flutter analyze` then reported no issues. The resolved analyzer was 14.5.0.
- Vikunja spec facts [V-src]:
  - v1 has a committed **Swagger 2.0** spec at `pkg/swagger/swagger.json` (`"swagger": "2.0"`); the directory is CI-generated (`AGENTS.md`).
  - v2 (Huma) serves the spec at runtime only: `/api/v2/openapi.json`, `/api/v2/openapi.yaml`, plus a down-converted `/api/v2/openapi-3.0.json` and `/api/v2/openapi-3.0.yaml` (`pkg/routes/routes.go:330-333`, `pkg/routes/api/v2/huma.go:75` `cfg.OpenAPIPath = "/openapi"`).
  - The web frontend generates its client with `@hey-api/openapi-ts` 0.99.0 from a temp spec (`frontend/openapi-ts.config.ts`, `magefile.go:1528-1537`).
- swagger_parser **1.45.0** (2026-09-25) [V-pub README]:
  - Supports OpenAPI 2.0, 3.0 and 3.1.
  - Generates **Retrofit** clients and json_serializable, freezed or dart_mappable DTOs.
  - Has include-path filters, `unknown_enum_value: true` and replacement rules.
- **Recommendation [I]:**
  - Commit `api/v2/vikunja-2.7.0.openapi-3.0.json`, fetched from a pinned `vikunja/vikunja:2.7.0` container.
  - Generate DTOs and clients with swagger_parser (`json_serializer: freezed`, `unknown_enum_value: true`, include only the v2 paths the app uses).
  - Hand-write the v1 adapter: v1 is frozen and the app needs a bounded set of endpoints.
  - Map both to hand-written domain models in a `VikunjaApi` port with V1 and V2 adapters chosen per server by capability detection from `/api/v1/info` (version) or by probing v2.

### 3.8 Authentication (OIDC and PKCE): flutter_web_auth_2 plus Vikunja's own OAuth server

**What Vikunja actually offers [V-src]:**

1. **Built-in OAuth 2.0 authorization server for native apps** (added in **2.3.0**, 2026-04-09; v2 endpoints in **2.4.0**) [V-src `CHANGELOG.md` lines 2654-2672, 2071].
   - `ValidateRedirectURI` accepts only schemes starting with **`vikunja-`** ("e.g. vikunja-flutter://callback") or loopback `http://localhost|127.0.0.0/8|::1` [V-src `pkg/modules/auth/oauth2server/client.go:25-53`].
   - PKCE is **required** with `code_challenge_method == "S256"` [V-src `authorize.go:94-104`].
   - The browser leg is the SPA route **`/oauth/authorize`** [V-src `frontend/src/router/index.ts:437-439`]. It works with whatever login the server has (local, LDAP, OIDC, TOTP). The SPA then calls `POST /api/v1/oauth/authorize` with body `{response_type:"code", client_id, redirect_uri, state, code_challenge, code_challenge_method}`; API tokens are rejected with 403 [V-src `authorize.go:28-71`].
   - Token endpoint: `POST /api/v1/oauth/token` (JSON) or `/api/v2/oauth/token`, which "Accepts application/x-www-form-urlencoded per RFC 6749 as well as JSON" [V-src `pkg/routes/api/v2/oauth.go:55,75`].
     - Request: `grant_type` (`authorization_code` or `refresh_token`), `code`, `client_id`, `redirect_uri`, `code_verifier`, `refresh_token`.
     - Response: `{access_token, token_type, expires_in, refresh_token}` [V-src `token.go:37-52`].
     - Errors: 400 on bad grant or code, 401 on bad refresh token.
2. **OIDC against external IdPs is a confidential, server-side exchange.** The SPA redirects to `provider.auth_url` with `redirect_uri=<frontend>/auth/openid/<key>` [V-src `frontend/src/helpers/redirectToProvider.ts:6-20`]. It then posts `{code, scope, redirect_url}` to the callback; the server does `Oauth2Config.Exchange` with its client secret [V-src `pkg/modules/auth/openid/openid.go:48-56, 614-626`]. There is no PKCE and the redirect URL must be registered at the IdP, so a mobile app cannot cleanly own this flow.

**Decision [I]:**

- For Vikunja **≥ 2.3**: open `https://<host>/oauth/authorize?response_type=code&client_id=vikunja-mobile&redirect_uri=vikunja-mobile://callback&state=<rnd>&code_challenge=<S256>&code_challenge_method=S256` with **flutter_web_auth_2 5.1.0** `FlutterWebAuth2.authenticate(url:, callbackUrlScheme: 'vikunja-mobile')`.
  - That is ASWebAuthenticationSession on iOS and Custom Tabs/Auth Tab on Android.
  - Exchange the code with dio (`crypto` 3.0.7 for SHA-256). This covers OIDC/LDAP/TOTP for free, because the user logs in on the Vikunja web page.
- For **older servers**: username/password (+TOTP) login form, or a pasted API token.
- flutter_appauth 12.1.0 lost:
  - Vikunja's OAuth server publishes no discovery document [I: none found in `oauth2server/`].
  - The v1 token endpoint binds JSON while AppAuth sends form-encoded data; only v2 (≥2.4) accepts both [V-src].
  - AppAuth-Android's latest Maven release is **0.11.1, last updated 2021-12-22** [V-web maven-metadata.xml]; AppAuth-iOS 3.0.0 shipped 2026-08-24.
- flutter_web_auth_2 caveats:
  - The UIScene migration landed only in **6.0.0-alpha.2** [V-pub changelog].
  - Stable 5.1.0 finds the presenter via `UIApplication.shared.delegate?.window` and then falls back to `UIApplication.shared.keyWindow` [V-pub source `FlutterWebAuth2Plugin.swift:110-118`]. This likely works under UIScene, but verify on device [I].
  - It applies KGP (AGP-9 built-in-Kotlin warning), tracked in issue #210, closed 2026-07-27 [V-web GitHub].

### 3.10 Local notifications with a "mark done" action

- flutter_local_notifications **22.3.1** (2026-09-13); 23.0.0-dev.3 exists [V-pub].
- Baseline since 21.0.0: Android API 24+, iOS 13+, compileSdk 36, UIScene-aware README.
  - 22.2.0 adds dismiss callbacks (`dismissIsolate`).

- **Background actions** [V-pub README lines 606-746]:
  - Actions without `DarwinNotificationActionOption.foreground` (iOS) or `showsUserInterface: true` (Android) run in a **background isolate**. The plugin starts a separate Flutter engine and calls `onDidReceiveBackgroundNotificationResponse`, a top-level function annotated `@pragma('vm:entry-point')`.

  - API names verified in source:
    - `DarwinNotificationCategory`, `DarwinNotificationAction.plain(id, title, options: {...})`
    - `DarwinNotificationActionOption.authenticationRequired | destructive | foreground`
    - `AndroidNotificationAction(..., showsUserInterface: false, cancelNotification: true)`
    - `AndroidScheduleMode.alarmClock | exact | exactAllowWhileIdle | inexact | inexactAllowWhileIdle`
    - `requestNotificationsPermission()`, `requestExactAlarmsPermission()`, `canScheduleExactNotifications()`, `requestFullScreenIntentPermission()`

The handler opens drift through `shareAcrossIsolates`, marks the task done locally plus an outbox row, tries `PATCH /api/v2/tasks/{id}` `{"done":true}` (v2.4+) or a full-object v1 update, and cancels the notification.
- **Android permissions:**
  - `POST_NOTIFICATIONS` runtime permission on 13+ (declared by the plugin).
  - `RECEIVE_BOOT_COMPLETED` to reschedule after reboot.
  - Exact alarms: `SCHEDULE_EXACT_ALARM` is **denied by default on Android 14+** for newly installed apps targeting 33+ that are not calendar or alarm-clock apps; check `canScheduleExactAlarms()` and send the user to `ACTION_REQUEST_SCHEDULE_EXACT_ALARM` [V-web https://developer.android.com/about/versions/14/changes/schedule-exact-alarms].
  - `USE_EXACT_ALARM` is auto-granted but restricted by Play policy to alarm, timer and calendar apps; a to-do app likely does not qualify [V-web secondary sources; I].
  - **Decision [I]:** declare `SCHEDULE_EXACT_ALARM` only; ask for it when the user enables "exact reminders"; otherwise fall back to `AndroidScheduleMode.inexactAllowWhileIdle`. `USE_EXACT_ALARM` could be considered for an F-Droid-only flavor.
- **Pending limits:**
  - iOS keeps only the **64** most recently scheduled notifications [V-pub README line 244].
  - Android `AlarmManagerService.DEFAULT_MAX_ALARMS_PER_UID = 500` [V-web AOSP references via search].
  - **Strategy [I]:** a rolling window that schedules only the soonest N (iOS ≤ 60, keeping slack for snoozes; Android ≤ 200). Recompute after every sync, app resume, background task and time-zone change (flutter_timezone 5.1.1 + timezone 0.11.1 for `zonedSchedule`). Use deterministic 31-bit IDs from `(taskId, reminderInstant)`, because Vikunja reminder IDs are not exposed: `json:"-"`, with JSON shape `{reminder, relative_period, relative_to: due_date|start_date|end_date}` [V-src `pkg/models/task_reminder.go:41-58`].

## 6. Risks (ranked)

1. **The material_ui transition is mid-flight.** The legacy library is due for deprecation in November, and the compatibility bridge is already deprecated. Some chosen deps still import `flutter/material` (flutter_widget_from_html_core 0.17.x, flutter_slidable, kalender, home_widget, webview_flutter, flutter_markdown_plus). Type mismatches appear wherever a dependency exposes Material types. Mitigation: prefer material_ui-native deps and wrap the others.
2. **cronet_http + AGP 9 manifest clash** (dart-lang/http#1932, open). It needs `android.uniquePackageNames=false`, and the embedded-Cronet flavor adds 6.5 MB.
3. **Built-in Kotlin cutoff:** cronet_http, flutter_web_auth_2, home_widget, patrol and workmanager_android still apply KGP, and Flutter warns that future versions will refuse to build.
4. **iOS background limits:** BGAppRefresh is opportunistic, so "web changes appear on the phone" is guaranteed only on open/resume. Interactive-widget intents may run in the extension process (home_widget docs, Apple deprecation of `ForegroundContinuableIntent`), which forces a native Swift path for widget "mark done".
5. **Notification limits:** 64 pending on iOS, 500 alarms per uid on Android, and exact alarms denied by default on Android 14+ with Play policy against `USE_EXACT_ALARM` for to-do apps. All of these need a rolling scheduler and inexact fallbacks.
6. **Keychain accessibility defaults to `unlocked`.** Background isolates fail to read tokens on a locked device unless `first_unlock_this_device` is set.
7. **Server-version matrix:** OAuth/PKCE needs Vikunja ≥ 2.3.0; v2 OAuth, AutoPatch and Markdown exchange need ≥ 2.4.0. Older servers need password/API-token login and the v1 full-object update path, so capability detection is mandatory.
8. **TipTap-in-WebView editor:** it must track Vikunja's TipTap version and extensions (3.31.3 today). It brings WebView startup cost and keyboard/IME quirks, and needs a JS bundle build step in CI.
9. **Dependency conflicts:** Sentry 9.x vs jni and connectivity_plus vs dbus show that Flutter plugin graphs churn weekly. Pin with a committed `pubspec.lock`, and gate upgrades through `flutter pub outdated` in CI.
10. **Riverpod 4 / freezed 4 churn:** Riverpod says a 4.0 may follow soon, and freezed 4 already broke `final` parameters because of Dart 3.13.
11. **Unverified locally:** iOS builds, flutter_web_auth_2 5.1.0 under UIScene, riverpod_lint plugin output, and home_widget Android callbacks after the app is killed (issue #318).
