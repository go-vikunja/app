# Roadmap

Condensed from [research/synthesis.md](research/synthesis.md) §4, which has each step's full scope, out-of-scope list and acceptance criteria. Where the synthesis and this page or the [decision log](decisions.md) disagree, this page and the log win.

## How steps are reviewed

- Each step is one branch and one PR.
- Each PR comes with:
  - screenshots or a recording;
  - a green CI run, including the server-version contract matrix when the API is touched;
  - a "decisions taken" list;
  - the open follow-ups.
- The next step starts only after approval.

**Definition of done** for every step:
- `flutter analyze` is clean.
- New logic has unit and widget tests.
- The UI works in dark mode and at 200 % text scale.
- New interactive elements have semantics.
- Strings are in ARB (en + de), new and changed ones with a description ([D68](decisions.md#d68-screen-readers-heading-levels-on-screen-titles-and-section-headers-one-announcer-with-the-apps-own-live-region-on-android-high-contrast-and-reduce-motion-followed-and-a-route-sweep-that-every-route-pushed-page-and-overlay-must-pass-wcag-22-aa-as-the-yardstick-with-written-deviations)), worded by the [glossary](glossary.md) ([D71](decisions.md#d71-complete-english-and-german-british-english-as-the-base-a-glossary-a-wording-pass-over-every-string-more-server-error-codes-in-the-apps-own-words-with-the-servers-detail-as-the-fallback-the-devices-language-followed-while-the-app-runs-names-sorted-with-accents-folded-an-app-language-row-that-opens-the-systems-page)).
- New routes, pushed pages and dialog, sheet, picker or menu calls have an accessibility sweep scenario or a written exemption (D68), and a route scenario its readable-width class in `readable_widths.dart` (D69); a task list inside a tab opens tasks through `openTaskDetail`, marks the one in the pane with `SelectedTaskHighlight` and has a pane scenario (D70).
- No secrets appear in logs.
- No new dependency is added without a note in the PR.
